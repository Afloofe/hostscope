# Verbs a responder needs

`hemostat help` (or --help) prints the full list, with every flag and the exit codes. These are the ones an incident usually needs. Every one of them is also on the Verbs tab of every view, so none of this needs a shell.

## Looking

- `hemostat console`: every sweep in this view. --once prints one frame and exits 7 if a sweep did not run in full, trust over an arrival snapshot that is there and was refused included. `hemostat gui` is the same view with real buttons, for a web console whose terminal mangles the keys or the mouse.
- `hemostat tui`: the posture view, live. `hemostat probe` and `hemostat build-info` print what the host and the image can do.
- `hemostat persistence`, `hemostat accounts`, `hemostat rootkit`, `hemostat suid`, `hemostat watchdog`, `hemostat overview`: single sweeps, printed.
- `hemostat snapshot` on arrival, then `hemostat drift`: every change since, graded. On Windows a binary something runs from a share, a device or through a link is never opened (a share is a connection that authenticates as you): it is CRITICAL, and the snapshot names it as not hashed. On the firewall both, like `fw rules`, take the signed vendor manifest as --manifest PATH, or from HEMOSTAT_MANIFEST.
- On the firewall the sealed stores under /root/hemostat/ share one 256 MiB, and the last 32 MiB is kept for the evidence fw block, fw confirm and undo seal before they write. accounts, persistence, trust and posture keep fewer files rather than reach into it, and name each one they did not keep as NOT JUDGED (exit 7); any other store, and theirs once nothing fits, is refused. Ship or copy the older stores off the box, then remove them, to make room.
- `hemostat trust`: the TLS trust store — every CA the host believes, where it came from, and whether its vendor ships it; a CA added since the snapshot that can sign for any name is CRITICAL. --all lists the distribution's own too.
- `hemostat usn` (Windows): an executable the NTFS change journal shows created and then deleted, the trace a payload that cleaned up after itself leaves, is CRITICAL. One replaced at its path by a file Microsoft signed (OneDrive updating itself), or the watchdog's own wrapper (watchdog.cmd) in C:\ProgramData\hemostat, so long as that folder is admin-only, is a note that says what lowered it; with nothing at that path now, a file there that is unsigned or signed by anyone else, or one under C:\Windows (where one Microsoft binary put in place of another, cmd.exe as sethc.exe, is itself the attack), it stays CRITICAL.

## Acting (dry run until --arm)

- `hemostat remediate`: a reversible removal for every catalogued persistence finding; --arm applies and writes an undo journal. With HEMOSTAT_GOLDEN set it first names the scored service units it holds back for this box's role (or why it holds none), and a finding in one of their unit files or drop-ins is left to you, with how to restore it from its package, instead of a mask or a stop; `--strip-line` refuses a line of them (exit 4). `remediate --anchors` lists the trust anchors you could remove, and `--remove-anchor <TOKEN>` takes one out and rebuilds the store (Linux). `remediate --pam` lists tampered PAM modules, each checked against the build baked for its installed package version (one with no such build baked is [skip], not checked), and `--restore-pam <PATH>` puts that build back, or refuses, naming the baked builds; armed, it tries a throwaway login from an unprivileged account before and after the swap, with the right password and a wrong one, and rolls the swap back if the login got in before and not after, or if a wrong password is taken after but was refused before.
- `hemostat remediate --seal-binaries` on arrival: copies the critical binaries into the root-only vault /var/lib/hemostat/arrival-bin. It has no dry run and needs no --arm: it seals at once, and --replace writes over the arrival copies. A vault that is a link or not root's alone is refused; a binary that is there and could not be sealed (not a regular file, over the size cap) is listed [skipped] and the run exits 7. A name that is a link (on Rocky, /usr/sbin/mariadbd and /usr/sbin/mysqld lead to /usr/libexec/mariadbd) is sealed once, as the real file it leads to, and listed [link]. `--restore-binary <PATH>` writes one back from that copy (dry run until --arm); given a link's name it writes the real file, never through the link, and refuses (exit 4) if the link no longer leads there: restore the real file by its own name and put the link back by hand. `remediate --pam` checks PAM modules against the baked stock builds; an /etc/os-release it cannot read is distro unknown, said so, exit 7, and so is a release nothing is baked for, named (ID, VERSION_ID and arch) beside the baked ones, where `--restore-pam` is refused (exit 4). With HEMOSTAT_GOLDEN unset it says so and checks nothing (exit 0).
- `hemostat remediate --remove-wmi <NAME>` (Windows): removes a permanent-WMI subscription from root\subscription: the consumer named exactly NAME, the bindings that reference it, and each bound filter no other binding uses. Every property and the MOF of each object goes to the fix log first, and nothing is removed if that write fails (`--remove-task` and `--remove-run` also log first). A NAME with a quote, backtick, `$` or control character, and any object that mentions DataDog, is refused: remove those by hand.
- `hemostat exec-block <PATH>` or --pid N: stop one binary starting again; --arm applies, --lift removes. Never sshd or its session helpers, the binary of a process holding a listening socket, anything a unit declared in /etc/hemostat/critical starts, anything a unit of this box's scored services starts with HEMOSTAT_GOLDEN set (while the service is down too), or the systemd-networkd and systemd-resolved binaries; stop a listening implant first, then block its file. Run it as root: as anyone else it cannot read other users' processes to say which socket each holds, so every block is refused (exit 4), and so is every kill, suspend, unit stop and unit mask `remediate` offers.
- `hemostat account`: --end-sessions, --purge-tickets, --expire-password, --drop-group G; --arm applies. whiteteam and the DataDog accounts (dd-agent, ddagentuser, datadog) are always refused.
- `hemostat passwd [--users a,b] --arm` (Linux, root, from a terminal): one new password, typed twice with echo off, for the IRSeC packet's users on this host, or the ones named; HEMOSTAT_GOLDEN must be set. Root, whiteteam and the DataDog accounts are never changed, and a name that is not a packet user here refuses the whole run. Without --arm it lists who would change, and marks the account you came in as. Each account's old hash is read before anything changes; the new password goes to chpasswd on a pipe, never on a command line, and is kept only once a test login with it gets in and one with a wrong password is refused (the failed-login count that leaves is cleared); otherwise the old password is put straight back. It is refused while pam_unix.so is not the stock module, since chpasswd hands the password to the PAM stack: restore it first with `hemostat remediate --restore-pam PATH --arm`. If the scoring engine logs in as one of these users, its check fails until the white team has the new password. It runs from a shell or `ssh -t`, not from the Verbs tab.
- `hemostat network`: the default-deny plan and its digest; --arm N --plan HEX applies exactly that plan with an automatic rollback in N seconds unless you --confirm, and is refused if the plan built at arm time is not the one you read. A plan that keeps tcp/21 also attaches the kernel's FTP conntrack helper to it, so the passive data connections an FTP server opens pass; the dry run lists its lines, and a kernel that cannot load it fails the arm, which rolls back with nothing applied. --egress denies outbound too, and keeps DNS, DHCP, syslog (514, 6514), the Wazuh agent (tcp 1514 and 1515) and the DataDog agent; with HEMOSTAT_GOLDEN set it also keeps SSH, RDP and WinRM (tcp 22, 3389, 5985 and 5986) to the team's two in-scope ranges, so the boxes you reach from this one stay reachable. With HEMOSTAT_GOLDEN set, every packet from and to the NetBird egress (10.T.1.99, out of scope in the packet's second version) passes both ways, a host running NetBird's agent is refused a default-deny, and the agent is never narrowed or killed. --block-pid N and --block-dest ADDR narrow egress instead; ADDR is one address unless --allow-subnet (at most /24 or /56), and never a syslog server this host forwards to. N is refused (exit 4), dry run included, when its cgroup holds a process that belongs to whiteteam or a DataDog account, or whose account cannot be named (a directory's accounts look like that), or one that ships logs (rsyslogd, syslog-ng, systemd-journald, systemd-journal-upload, wazuh-agentd, ossec-agentd, the DataDog agent): the rule blocks the whole cgroup. Its state is kept in /var/lib/hemostat, and the arm is refused, with nothing applied, if that is a link or anyone but root can write it. --revert deletes the table the arm added (`nft delete table inet hemostat`, or `inet hemostat_narrow` for a narrowing) and nothing else: every other table, firewalld's, ufw's or Docker's, is left as it is, and the automatic rollback does the same. A copy of the ruleset from before the arm is kept, for reference, in /var/lib/hemostat. It exits 6, naming the command to run by hand, if the table is still loaded afterwards.
- `hemostat fw block CIDR --alias NAME --tracker N` (the firewall): one address unless --allow-subnet (refused while HEMOSTAT_GOLDEN is set), never the box's own NTP or syslog server. With HEMOSTAT_GOLDEN set the packet's scope holds as well (rules 14 and 15): only one address in your team's 10.x.1.0/24 or 192.168.x.0/24, and never one of the packet's own hosts (your scored boxes, barrier, timing, and the NetBird egress 10.x.1.99 the packet's second version adds); the team number x comes from $HEMOSTAT_TEAM or the box's own addresses. So the scoring engine, which is outside both ranges, can never be blocked, and neither can anything else out of scope. fw statekill and network --block-dest hold to the same rule; --arm puts it live until its deadline. `hemostat fw confirm ID --arm` makes it persistent, and without --arm is a dry run. A confirm that fails after the write says the block is persistent, and `hemostat undo ID` lifts it. Undo takes a confirmed block out of config.xml even when its rule is disabled and pf has no table for it, and says so, so the rule does not load it again. Confirm and undo, like the block, need the signed vendor manifest (--manifest PATH or HEMOSTAT_MANIFEST): the commands the block prints, and [p Keep] and [u Revert] in the Verbs tab, carry the one it was given.
- `hemostat services --restore`: start every DOWN scored service this box owns (needs HEMOSTAT_GOLDEN); --arm applies, `--every SECS` keeps watching. A start counts as FIXED only once the scored port answers again. A unit that is running with its port shut is not restarted: it is shown as RUNNING, PORT CLOSED for you to fix, with where to look. A box it cannot check (a hostname that names no packet role, an unreadable socket table) says NOT CHECKED and exits 7, never "all up"; the watchdog says NOT CHECKED that tick and keeps watching. The role is the hostname's first label, or the one role among its `-`/`_` parts (`team5-garage` is garage; `garage-pitlane` is neither); `HEMOSTAT_ROLE=<role>` names it outright, and every output says when it did. A listening port the firewall drops is UNREACH, and one it cannot tell about is UNKNOWN.
- `hemostat services --compose-up <PROJECT|FILE>...`: bring up only the Docker Compose projects you name, or one `compose down` removed, from its compose file; with none named it lists what is down and changes nothing. A project comes back with every compose file it was started with (an override too), each its own -f in order, and the dry run shows them all; if any of them is not a file here, the project is refused. If any named one cannot be acted on, nothing is. --arm applies and journals each `up`.
- `hemostat services --install-watchdog [--every SECS]`: the uptime watchdog as a systemd service, running under the policy environment it was installed with. It refuses a link or a different unit at its path. `--uninstall-watchdog` removes it in any image, and exits 6 if anything of it is left. Both are dry runs until --arm.
- `hemostat undo <JOURNAL>`: reverse an armed remediation.
- On Windows, `hemostat remediate --remove-run <NAME>`: delete a rogue Run autostart value. Its type and exact data are kept first in a single-value .reg file in a new admin-only directory under %ProgramData%; the undo, printed and logged to fixes.log, is `reg import` of that file. A string value stored without its closing NUL comes back with one (the same text, two bytes longer), and the dry run and the log say so. A value that cannot be kept exactly is refused (exit 4), and so is DataDog's.
- `hemostat ticket --op <OP> --ttl <SECS> --out <FILE>`: mint an authorization ticket; point $HEMOSTAT_TICKET at it.

## Acting on Windows (dry run until --arm)

Each runs only in a build that carries its module; otherwise it exits 8 (NOT-BUILT), dry run included. What they keep goes in C:\ProgramData\hemostat, which HEMOSTAT makes admin-only; if that folder (or one inside it) already exists and someone else owns it or can write to it, every one of them refuses it, and the refusal ends with the command that clears it. Run that command from an elevated prompt, then run the verb again: `takeown /f <folder> /a /r` when your own account owns it and nobody else can write in it (an older HEMOSTAT leaves it that way on Windows 10 and 11), otherwise `move <folder> <folder>.untrusted-<time>`, which keeps what was in it to look at.

- `hemostat kill --pid N`: end one process. Refused: System/Idle, the critical processes, a shared svchost, a scored service's image (DNS, IIS, Telnet, OpenSSH), DataDog, your own shell and connection, and a process whose image cannot be read. A process with a listening port is refused too; add --allow-listener once you have checked it is the red team's.
- `hemostat quarantine <PATH>`: move one file into the vault. Refused under the Windows or Program Files directories or DataDog's, judged after 8.3 names and links resolve. Its full path is recorded beside it before it moves; the command to move it back is printed only when the path holds nothing a shell reads as syntax (`$`, a quote, a backtick, `%`, `!`), and otherwise the output says to move it by hand.
- `hemostat account --disable <USER>`: disable a local user. Refused for the account your session runs as, for the last enabled administrator, and for a built-in by relative id (500-504: Administrator, Guest, krbtgt, DefaultAccount, WDAGUtilityAccount) whatever it is called. The output and the fix log name the account's SID: the undo is for that SID only, so check the name is still that account before you run it.
- `hemostat remediate --remove-task/--remove-run/--remove-wmi <NAME>`, `--seal-binaries`, `--restore-binary <PATH>`: persistence removal and the binary vault. `--remove-task` keeps the task's own XML as UTF-16 in a new file each time and refuses a task whose XML would not re-create it, DataDog's, and a NAME with a quote, backtick, `$`, `%`, `!` or control character. A restore checks the vault is still admin-only before it writes; restart the service afterwards with `sc stop <service>` and `services --restore --arm`, not a bare `sc start`.
- `hemostat services --install-watchdog --arm`: the SYSTEM task runs a copy of this binary kept in C:\ProgramData\hemostat\bin, not the file you launched. A HEMOSTAT_ROLE set when you install it is carried into the task. Remove it with `services --uninstall-watchdog --arm`.
- `hemostat services --restore` and its watchdog (Windows) start a scored service only while it is configured to run its stock binary: the image `sc qc` names (dns.exe, lsass.exe for NTDS, tlntsvr.exe, or svchost.exe) under System32, and for WinRM, SMB and IIS the ServiceDll (WsmSvc.dll, srvsvc.dll, inetsrv\iisw3adm.dll). Anything else is NOT STARTED and left to you (exit 4; the watchdog writes it to the fix log once): put the service's binary path back (`sc qc <service>`, `sc config`), and the next tick starts it.
- `hemostat firewall --allow <PORT>` (Windows): a rule already named `mahoraga-allow-<PORT>` counts only if it is enabled, inbound, an Allow, and TCP on that port alone; any other rule with that name is refused, saying what it is — look at it and remove or rename it by hand.
- The fix log, C:\ProgramData\hemostat\fixes.log, is never written through a link: if it is a link, a directory or a hard link to another file, the line is not written and the refusal ends with the command that moves it aside.

## Evidence and the collector

- `hemostat collect [DIR]`: the sweeps into a sealed, hash-chained store. `hemostat verify <DIR>` checks it with no key; `hemostat read <DIR>` decrypts it with $HEMOSTAT_RECOVERY_KEY.
- `hemostat ship --to <HOST:PORT> --collector-key <HEX> --receipt-key <HEX> <STORE>...`: push sealed stores to a collector. On the collector, `hemostat collector ingest <DIR>`, then `hemostat queue`.
- `hemostat queue list`, `queue show <ID>`, `queue ack <ID>`, `queue resolve <ID> --as true-positive|false-positive|benign --reason <TEXT>`, `queue note <ID> --reason <TEXT>`: the same triage without the terminal view.

## Exit codes

0 ran · 1 failed · 2 usage · 3 authorization denied · 4 policy refusal · 5 dry run, nothing applied · 6 the enforcer failed (NOT success) · 7 a sweep could not run in full, a named vendor manifest was refused, or `detect` had to cut an over-long field (partial, not clean) · 8 NOT-BUILT in this variant.
